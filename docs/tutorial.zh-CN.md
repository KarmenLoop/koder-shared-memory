# KODER Shared Memory：从打包到第一次交接

[English](tutorial.en.md) | 简体中文 · [项目首页](../README.zh-CN.md)

本教程对应 **v1.0.0**，把[开始使用](getting-started.md)、[宿主接入](integration.md)、[常见问题](faq.md)中的可操作路径收成「安装 → 练习 → 排查 → 升级」一条线。英文技术契约正文仍以原文档为准；本页提供完整中文步骤与边界说明。

## 1. 开始之前

宿主需要能够：

- 加载技能，并且
- 提供持久记忆工具。

跨渠道还需要可用的聊天连接器；跨设备需要共享服务与已验证的设备关联。

技能包**不**自带模型订阅。宿主、模型提供方、消息平台与存储服务可能另有要求或费用。本仓库不负责配置或购买这些服务。

## 2. 打包与导入

在仓库根目录（Python 3.10+）：

```bash
python3 scripts/check_repository.py
python3 scripts/package_skill.py
```

用宿主的技能或资源导入器导入 `dist/koder-shared-memory.skill.zip`。界面因版本而异。

若宿主直接加载目录，把 `skills/koder-shared-memory/` 放到其文档规定的技能目录，并保持 `SKILL.md` 与 `agents/openai.yaml` 在一起。**不要**把凭据或运行时数据拷进技能包。

在所有要关联的入口启用技能。仅项目或仅对话设置会限制可用范围。单靠元数据不能保证每轮默认回忆——需要默认回忆时，把每轮检索与落盘接到宿主会话流程（见[宿主接入](integration.md)）。

## 3. 检查宿主连接

确认宿主能够：

1. 用**已验证**身份解析账号、设备与记忆空间。
2. 写入记录并在重启应用后取回。
3. 把每个已关联渠道映射到同一空间。
4. 用**真实回执**报告同步状态。
5. 在每一轮（含桌面任务与恢复的对话）加载技能。

「导入成功」**不等于**上述能力已具备。

## 4. 第一次交接（首个练习）

使用**测试空间**，内容按关联群全员可见来准备。

**在桌面：**

> 记住演示评审在周四。样例报告已起草，但图表还要审。

**在已关联私聊：**

> 演示评审前还剩什么？

**作为关联群的另一位成员：**

> 接手演示评审。哪些已就绪，哪些还要做？

核对检索到来源、任务状态与**回复落点**。再到第二台实体设备重复，确认源记录已被确认、接收设备确实取到。

### 群组可见性

默认允许关联群每位成员使用该空间中的关联私聊记忆。关联时必须说明。不应进入该共享范围的材料，请使用单独空间。

## 5. 排查问题

- **导入成功但回忆为空：** 可能缺少持久工具、空间绑定或每轮加载——见[宿主接入](integration.md)。
- **答错了会话：** 对话仍各自路由；不仅看记忆内容，还要核对回复落点。
- **群里意外看到私聊细节：** 复查关联披露与空间隔离（[faq](faq.md)）。
- **离线 / 同步挂起：** 本地可继续；其他设备在真正传过去之前读不到。如实区分 pending 与 confirmed。
- **文件没到另一台设备：** 记忆存的是引用；传文件需要单独授权的资源路径。
- **换其他宿主：** Markdown 可移植，但需该宿主提供必需工具并通过行为场景（[validation](validation.md)）后才算兼容。

## 6. 升级、回退与卸载

1. 把记忆数据与宿主配置放在技能包目录**之外**。
2. 下载或重新打包已验证版本；宿主拒绝覆盖时安装到新目录。
3. 切换版本后关闭或刷新宿主会话。
4. 回退：恢复旧技能目录并刷新发现。
5. 卸载：只删除你安装的技能目录；本包不安装系统服务。宿主侧记忆库与账号绑定需按宿主流程另行清理。

发布或依赖新包前阅读 [CHANGELOG.md](../CHANGELOG.md) 与 [RELEASE.md](../RELEASE.md)。

## 7. 接入要点（检查清单）

| 职责 | 可观察结果 |
| --- | --- |
| 从已验证绑定解析空间 | 稳定的空间身份与访问范围 |
| 带来源检索 | 含版本与删除过滤的记录 |
| 带事件身份落盘 | 持久本地写回执 |
| 同步 | 幂等确认；区分已上传 / 已确认 / 已在目标设备读到 |
| 执行分离 | 不静默重放队列或转移审批 |
